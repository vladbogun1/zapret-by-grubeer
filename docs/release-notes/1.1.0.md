A new interface, real strategy testing, and releases built by CI.

## The interface was rebuilt

The application now has a proper dashboard: engine state, the strategy in use, uptime, the network profile,
a service check, system status, ranked strategy results and a history of what actually happened — over a
status strip that tells you in one line whether you need to do anything.

**It is no longer Russian-only.** Every string comes from a translation table; Russian and English ship, and
the language switches instantly from the title bar or Settings, with no restart. Adding a language is a
table and one line of code.

All seven pages — Главная, Стратегии, Сервисы, Диагностика, Сеть, Настройки, Обновления — share one visual
language and one set of design tokens.

## Strategy testing that means something

The full test drives upstream's own test utility across every discovered strategy, unattended, and turns its
output into a ranking. Results are stored with the engine version and the connection they were measured on,
so a sweep from another network is shown but marked stale instead of passing for current.

**When the test cannot separate the strategies, nothing is crowned.** On a connection where nothing under
test is blocked, every strategy passes everything with the same latency — and the application says there is
nothing to choose between rather than pointing at an arbitrary row. A latency spread under 10 ms is treated
as measurement jitter, because that is what it is.

## Per-network memory

The strategy you apply is remembered for the connection you applied it on, identified by a one-way
fingerprint that cannot be turned back into a network name or a gateway address. A home connection and a
mobile one keep their own choices.

## Fixes

- A leftover engine process holding the WinDivert driver made every subsequent start fail with a bare
  `exit code 1`. The manager now reclaims its own orphaned processes before starting, which is what makes
  start-after-restart reliable.
- Hosts and IPSet lists are fetched from upstream's repository, because release archives do not contain the
  `.service` directory at all — so those two features previously could not work for anyone installing from a
  release. Their absence is also no longer reported as a compatibility limitation, since it never was one.
- Unhandled interface errors are written to `%LocalAppData%\ZapretByGrubeer\ui-crash.log` instead of leaving
  you with a Windows error dialog and nothing to send.

## Not in this release

The Сервисы page still holds run mode and filters rather than the per-service catalog with toggles and a
custom-service editor. That needs a service registry over the user domain lists and is being built
separately, rather than shipped half-finished.
